Two reading depths

A small label, then the register that can defend it.

FEATURE_FACTS.md holds zero to 12 approved rows. Initialization leaves the selection empty. A scanner can propose candidates. It cannot silently curate them.

.featurefacts/ keeps the known capabilities inside a declared survey scope: surfaces, evidence, stale locators, and publication choices. It is not a claim that every capability was found.

Scan one TypeScript repo

Default scan does not execute target code, use the network, or call a model.

git clone https://github.com/Catalyst-Forge-LLC/feature-facts
cd feature-facts
pnpm install

pnpm featurefacts init  --root ../my-app
pnpm featurefacts scan  --root ../my-app
pnpm featurefacts show  --root ../my-app
pnpm featurefacts check --root ../my-app

The CLI runs from a clone of the FeatureFacts repository. It is not on npm yet, and it is not a runtime dependency of the app you scan. First ecosystem: TypeScript/Node. Unsupported inputs report unsupported, not a fabricated inventory. Confirming a feature, approving public rows, and selecting label IDs stay attributed maintainer decisions.
