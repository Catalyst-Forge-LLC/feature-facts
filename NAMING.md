# Naming

**FeatureFacts** is the chosen public name. Write it as one word, with both capital Fs. Write the family as **xFacts**, with a lowercase x.

| Identifier | Value |
|---|---|
| Public question | What can this product do? |
| Family layer | Terrain |
| Root label | `FEATURE_FACTS.md` |
| Label version field | `feature_facts_version` |
| Other artifact version field | `schemaVersion` |
| Register directory | `.featurefacts/` |
| Planned CLI/package | `featurefacts` |
| Planned site | featurefacts.dev |

ForgeTopo was a working title for the map engine. It is not a second public product. Previously considered names are not current package-availability findings, and this revision makes no availability claim about them.

Keep the map metaphor in the visual identity or occasional explanation. Use **feature, dependency, documentation, test, register, and evidence** in normative contracts, command help, and actions. Do not make users translate those nouns into contours, drainages, deeds, or benchmarks.

A concise public explanation:

> Know what your product can do, where its evidence lives, and which capabilities need documentation or test review.
>
> FeatureFacts maintains a compact capability label backed by an inspectable feature register.

Qualify automated discovery by supported ecosystem and inspected scope. Do not promise a complete product inventory or claim market-wide uniqueness without separate research.
